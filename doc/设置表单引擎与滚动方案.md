## 1. 决策（ADR）

**不引入 GUI 框架。** 在 `screenloom-app/src/settings/` 内自建两个模块：

| 模块 | 职责 |
|---|---|
| `form.rs` | **运行时表单模型**：`Vec<Section>` + 字段访问器（读/写/校验），替代 `&'static [Section]` 常量表 |
| `scroll.rs` | **滚动视口**：内容坐标 ↔ 视口坐标、偏移夹取、滚轮/键盘/拖动、滑块几何 |

保持不变的：Win32 消息循环、GDI+ 自绘、原生 `EDIT`、`ScreenloomFlatButton`、JSON 主题热重载、
`key=value` 配置文件与 BOM、三处入口、`--record-settings` 的窗口类名与标题。

### 1.1 为什么不引框架

| 约束 | 事实 | 框架要付的账 |
|---|---|---|
| 事件循环所有权 | `settings::open()` 在**调用线程**上跑嵌套 `GetMessageW`，托盘/热键靠同一线程派发 | `winit`/`eframe`/`slint` 必须独占一个线程的事件循环；主线程若 `join`，设置打开期间托盘与热键**全部停摆** |
| 依赖纪律 | 全项目 **4 个 crate**、exe ≈ 2 MB、MSRV **1.75**、零警告 | egui 树 40+ crate / +2～4 MB / MSRV 抬到 1.8x；Tauri 还要 WebView2 运行时 + Node 工具链 |
| E2E 契约 | 脚本按**窗口类名 + EDIT 下标 + `BM_CLICK`** 驱动（见 §7） | 控件树全变，脚本全废，只能改成 UIA 或纯截图断言 |
| 设计语言 | `theme.rs` 23 色 + 6 圆角，JSON **400ms 热重载**，GDI+ 直绘 | 框架是另一套样式/绘制系统，tokens 要重写一遍，热重载要重做 |

真正的痛点不是"没有渲染框架"，而是"没有数据驱动的表单模型"和"没有滚动"——两者都已在现有栈内解决。

### 1.2 结果

| | 内容 |
|---|---|
| 加字段 | **1 个 `Field` 变体 + 1 条 `Row` + 一对 get/set 函数**；`layout` / `paint` / `controls` / `validate` 全部不用动 |
| 两个窗口 | 录屏设置并入同一套引擎（同一窗口过程，两个类名/标题），`record_settings.rs` 的 538 行重复实现删除 |
| 滚动 | 内容超过工作区时窗口封顶，右侧出滚动条；滚轮 / `PgUp`·`PgDn` / `Home`·`End` / 拖动 / Tab 自动显现 |
| 外观 | 不溢出时窗口尺寸与 v2 **逐像素一致**（`default_size_unchanged` 锁定） |
| E2E | 3 个现有脚本原样通过（类名、EDIT 顺序、`BM_CLICK`、深色像素判据全部不变） |

## 3. 目标 / 非目标

**目标（全部达成）**

1. 表单由**运行时数据**描述：`Form { sections: Vec<Section> }`，字段的读/写/校验随字段声明。
2. 滚动：内容超过可视区时出滚动条；**不溢出时窗口尺寸与改动前逐像素一致**。
3. 两个设置窗口复用同一套布局、绘制、校验、控件构建代码。
4. 现有 E2E 与配置格式零改动。
5. 单测覆盖字段完整性、值往返、滚动数学。

**非目标**

- 换渲染框架、改外观、改配色、加动画。
- 合并成一个带页签的窗口（仍保留两个窗口，只是共用引擎）。
- 修好自绘控件的无障碍语义。
- 支持窗口缩放 / 运行时换 DPI。

## 4. 表单模型

### 4.1 结构

```rust
pub(crate) enum Field { /* 截图 13 + 录屏 10，见 §12 */ }
pub(crate) enum Kind { Edit, Password, Check, Combo }   // 数字字段 = Edit + 范围校验

pub(crate) struct Widget { field: Field, kind: Kind, text: &'static str, access: Access }
pub(crate) struct Row { label: &'static str, widgets: Vec<Widget>, trailing: Option<Trailing> }
pub(crate) struct Section { title: &'static str, note: &'static str, rows: Vec<Row> }
pub(crate) struct Form { kind: FormKind, sections: Vec<Section> }
```

构造函数：

```rust
pub(crate) fn capture_form(cfg: &Config) -> Form;                      // 13 字段
pub(crate) fn record_form(cfg: &Config, mons: &[MonitorInfo]) -> Form;  // 10 字段
```

只有下拉候选项需要 `Vec<String>`（显示器列表是运行时数据），其余标签都是 `&'static str`。

### 4.2 访问器

```rust
type TextSet = fn(&mut Config, &str) -> Result<(), String>;  // Err = 用户可读提示
pub(crate) enum Access {
    Text { get: TextGet, set: TextSet },
    Bool { get: BoolGet, set: BoolSet },
    Choice { items: Vec<String>, get: ChoiceGet, set: ChoiceSet },
}
```

用**函数指针**而不是 `trait` 对象：无堆分配、编译期查签名、单测可直接调 `set` 做干跑校验。

### 4.3 三个"不平凡"的字段（抽象的试金石）

| 字段 | 界面显示 | 配置 | 变换 |
|---|---|---|---|
| 录制码率 | `8.0`（MB/s） | `record_bitrate: u32`（bps） | ×1e6 / ÷1e6，范围 0.1～100 |
| 录制显示器 | 「主显示器（自动）」/「显示器 N · WxH · S%」 | `record_monitor: i32`（`-1` = 自动） | 下标 0 ↔ `-1`；下标 i ↔ `i-1`；越界夹取 |
| API Key | 掩码 | `ai_api_key` | 原样 + `ES_PASSWORD` |

### 4.4 值生命周期

- **唯一真值** = `State.draft: Config`。
- `Bool` / `Choice`：点击后立刻写回 `draft`（不再维护 `checks` / `combos` 两张表）。
- `Text`：建窗后 `fill_text()` 用 `get` 填充；保存前 `commit_text()` 解析写回，非法值**保留原值**。
- `validate()`：对每个文本字段的当前文本跑一次 `set` 干跑（写在 clone 上），返回第一条 `Err`。
- 保存：`validate()` → `take_result()`（提交 + clone）→ `Config::save`。
  **不再需要"销毁窗口前收集"**，`State.result` 只在保存时赋值。
- 删除了 `State::fill` / `State::collect` / `State::edit_text` 与整个 `validate.rs`。

### 4.5 焦点顺序

`Form::focus_items()` 生成：控件按界面顺序 → 行尾「浏览…」→ 保存 → 取消。
截图设置仍是 **16 站**（13 字段 + 浏览 + 保存 + 取消），顺序与改动前完全一致（E2E 依赖）。

## 5. 滚动视口

### 5.1 坐标与几何

- **内容坐标**：`compute_layout` 的输出，`y` 从 0 起，高度 = `content_h`（不含底栏）。
- **视口坐标**：客户区，底部按钮固定，不参与滚动。

```text
footer_y   = client_h - PAD - BTN_H              // 固定底栏顶边
viewport   = (0, 0, WIN_W, footer_y)             // 可滚动区域
screen_y   = content_y - scroll.y                // 内容 → 屏幕
scroll.max = max(0, content_h - viewport.h)
client_h   = clamp(content_h + FOOTER_GAP + BTN_H + PAD,
                   MIN_CLIENT_H(480), screen_h - 80)
```

内容不溢出时 `viewport.h == content_h + FOOTER_GAP`，`scroll.max` 恰好为 0 —— **不画滚动条**。
回归测试 `default_size_unchanged` 锁定 `client_h`：1.0 → 652，1.25 → 829。

### 5.2 滚动状态

```rust
pub(crate) struct Scroll { y: i32, max: i32, viewport_h: i32, hover: bool, drag: Option<i32>, acc: i32 }
```

`clamp` / `wheel` / `page` / `home` / `end` / `ensure_visible` / `thumb` / `begin_drag` / `drag_to` / `click_track` 全部是纯数学，可单测。

### 5.3 输入映射

| 输入 | 行为 |
|---|---|
| 滚轮 | 3 行/格；`acc` 累加，兼容高精度触控板的小 delta；`EDIT` 子类把 `WM_MOUSEWHEEL` 转给宿主 |
| `PgUp` / `PgDn` | 视口 80% |
| `Home` / `End` | 0 / max |
| `Tab` / `Shift+Tab` | 焦点移动后 `ensure_visible`，视口外的控件自动滚入 |
| 拖动滑块 | `SetCapture` + 按比例映射 |
| 点击轨道 | 上 / 下翻一屏 |
| 下拉菜单打开时 | 先 `close_combo` 再滚动（菜单位置在打开时算死） |

### 5.4 子控件同步

原生控件**创建一次**，按内容坐标摆放；滚动只改位置：

- `edit_inner()` 统一「外框矩形 → EDIT 内缩矩形」，创建与移动共用，避免滚动后 EDIT 盖住圆角外框。
- `BeginDeferWindowPos` / `DeferWindowPos` 批量移动，失败时退回逐个 `SetWindowPos`。
- 窗口样式加 `WS_CLIPCHILDREN`（**不是**类样式 —— 放进 `WNDCLASS_EX.style` 会让 `RegisterClassExW` 直接失败）。
- 滚出视口的控件不隐藏，由父窗口裁剪；命中测试把鼠标 `y` 加回 `scroll.y`。

### 5.5 绘制

`draw_scene` 先 `g.clip_rect(viewport)`，所有 `y` 加 `-scroll.y`，只画与视口相交的面板/行；
最后 `clear_clip` 再画滚动条（内容不溢出时直接返回）。

### 5.6 主题新增键（旧 JSON 不受影响）

| 键 | 默认 | 说明 |
|---|---|---|
| `scroll_track` | `#14FFFFFF` | 轨道 |
| `scroll_thumb` | `#40FFFFFF` | 滑块 |
| `scroll_thumb_hover` | `#66FFFFFF` | 悬停 / 拖动 |
| `radius_scroll` | `3.0` | 滑块圆角（逻辑像素） |

## 10. 踩坑备忘（新增，已并入契约附录）

1. **`WS_CLIPCHILDREN` 不能放进 `WNDCLASSEXW.style`** —— 它不是类样式，`RegisterClassExW` 会失败（表现为"注册设置窗口类失败"，窗口根本不出来）。要放在 `CreateWindowExW` 的窗口样式里。
2. **EDIT 的内缩矩形要统一** —— 创建和滚动同步都用 `edit_inner()`，否则第一次 `sync_children` 就把 EDIT 撑满外框，圆角被盖住。
3. **滚动后命中测试必须加回偏移** —— `hit_widget` 用 `y + scroll.y`，否则滚过之后点复选框会点错。
4. **下拉菜单打开时不能滚动** —— 菜单位置在打开时算死，滚动前先 `close_combo`。

## 11. 何时重新考虑框架 / 无障碍

满足**任一**条件时重启选型（此时渲染层可替换，表单模型保留）：

| 触发条件 | 候选 |
|---|---|
| 设置 ≥ 5 页或字段 ≥ 30 个 | `egui`（纯 Rust、试点成本最低；需抬 MSRV、验中文 IME） |
| 设计稿由前端/设计系统产出，需要动效与富文本 | `wry` + WebView2 **子窗口**（`build_as_child`，保住 Win32 消息循环） |
| 需要跨平台 | `egui` / `slint`（授权需确认） |
| 设置变成带搜索、插件、实时预览的控制中心 | Tauri 2（需接受 WebView2 + 前端工具链） |

无障碍仍是已知缺口：复选框 / 下拉是纯自绘，UIA 识别不到。
低成本的下一步是把它们换成真正的 `BUTTON` / `COMBOBOX` + `SetWindowTheme(hwnd, "DarkMode_Explorer", null)` + owner-draw 项，
保留外观的同时恢复语义——不需要框架。
