## 1. 决策（ADR）

**不引入 GUI 框架。** 在 `screenloom-app/src/settings/` 内自建两个小模块：

| 模块 | 职责 |
|---|---|
| `form.rs`（新） | **运行时表单模型**：`Vec<Section>` + 字段访问器（读/写/校验），替代 `&'static [Section]` 常量表 |
| `scroll.rs`（新） | **滚动视口**：内容坐标 ↔ 视口坐标、偏移夹取、滚轮/键盘/拖动、子控件同步 |

保持不变的：Win32 消息循环、GDI+ 自绘、原生 `EDIT`、`ScreenloomFlatButton`、JSON 主题热重载、
`key=value` 配置文件与 BOM、三处入口、`--record-settings` 行为。

### 1.1 为什么不引框架

| 约束 | 事实 | 框架要付的账 |
|---|---|---|
| 事件循环所有权 | `settings::open()` 在**调用线程**上跑嵌套 `GetMessageW`，托盘/热键靠同一线程派发 | `winit`/`eframe`/`slint` 必须独占一个线程的事件循环；主线程若 `join`，设置打开期间托盘与热键**全部停摆** |
| 依赖纪律 | 全项目 **4 个 crate**、exe **1.93 MB**、MSRV **1.75**、零警告 | egui 树 40+ crate / +2～4 MB / MSRV 抬到 1.8x；Tauri 还要 WebView2 运行时 + Node 工具链 |
| E2E 契约 | 4 个脚本按**窗口类名 + EDIT 下标 + `BM_CLICK`** 驱动（见 §7） | 控件树全变，脚本全废，只能改成 UIA 或纯截图断言 |
| 设计语言 | `theme.rs` 24 色 + 5 圆角，JSON **400ms 热重载**，GDI+ 直绘 | 框架是另一套样式/绘制系统，tokens 要重写一遍，热重载要重做 |

结论：框架能解决的是「表单书写效率 + 无障碍」，这两件事都可以用**远低于框架的代价**在现有栈里做到。
真正的痛点不是"没有渲染框架"，而是"没有数据驱动的表单模型"和"没有滚动"（§2）。

### 1.2 后果

| | 内容 |
|---|---|
| 正面 | 加字段：**4 处改动 → 1 条 `Row`**；两个设置窗口共用一套布局/绘制/校验；内容超高自动滚动；`collect()` 的"销毁窗口前必须读值"陷阱消失 |
| 负面 | `settings/` 短期 **+≈400 行**（form 260 / scroll 140），并要长期维护一套自研表单引擎（无社区文档） |
| 中性 | **外观零变化**；E2E 零改动；配置文件格式不变 |

## 3. 目标 / 非目标

**目标**

1. 表单由**运行时数据**描述：`Form { sections: Vec<Section> }`，字段的读/写/校验随字段一起声明。
2. 滚动：内容超过可视区时出滚动条，滚轮/键盘/拖动/焦点自动显现全部可用；**不溢出时窗口尺寸与现在逐像素一致**。
3. 两个设置窗口复用同一套布局、绘制、校验、控件构建代码。
4. 现有 E2E 与配置格式**零改动**。
5. 新增单测覆盖字段完整性、值往返、滚动数学。

**非目标（本期）**

- 换渲染框架、改外观、改配色、加动画。
- 合并成一个带页签的窗口（留到 Phase 3，见 §9）。
- 修好自绘控件的无障碍语义。
- 支持窗口缩放 / 运行时换 DPI。

## 4. 表单模型

### 4.1 结构

```rust
pub(crate) enum Field { /* 截图 13 + 录屏 9，见 §12 */ }
pub(crate) enum Kind { Text, Password, Number, Bool, Choice }

pub(crate) struct Widget {
    pub(crate) field: Field,
    pub(crate) kind: Kind,
    pub(crate) text: &'static str,   // Bool 的标签；其它为空
    pub(crate) access: Access,       // 见 4.2
}

pub(crate) struct Row {
    pub(crate) label: &'static str,
    pub(crate) widgets: Vec<Widget>,
    pub(crate) trailing: Option<Trailing>,  // 「浏览…」
}

pub(crate) struct Section { title, note, rows: Vec<Row> }
pub(crate) struct Form { kind: FormKind, sections: Vec<Section> }
```

`SECTIONS` 常量改成构造函数：

```rust
pub(crate) fn capture_form(cfg: &Config) -> Form;                       // 13 字段
pub(crate) fn record_form(cfg: &Config, mons: &[MonitorInfo]) -> Form;  // 9 字段
```

字段标签用 `&'static str` 足够；**只有下拉候选项需要 `Vec<String>`**（显示器列表是运行时数据）。

### 4.2 访问器（关键设计）

字段的"读显示值 / 写回配置 / 校验"三件事跟着字段走，而不是散在 `fill`/`collect`/`validate` 三个 `match` 里：

```rust
type TextGet = fn(&Config) -> String;
type TextSet = fn(&mut Config, &str) -> std::result::Result<(), String>;  // Err = 用户可读的提示
type BoolGet = fn(&Config) -> bool;
type BoolSet = fn(&mut Config, bool);
type ChoiceGet = fn(&Config) -> usize;
type ChoiceSet = fn(&mut Config, usize);

pub(crate) enum Access {
    Text { get: TextGet, set: TextSet },
    Bool { get: BoolGet, set: BoolSet },
    Choice { items: Vec<String>, get: ChoiceGet, set: ChoiceSet },
}
```

用**函数指针**而不是 `trait` 对象：`Bool`/`Choice` 的 `Access` 可 `Copy`、无堆分配、编译器能查签名、单测可以直接调
`set` 做干跑校验。

### 4.3 三个"不平凡"的字段（这套抽象的试金石）

| 字段 | 界面显示 | 配置 | 需要的变换 |
|---|---|---|---|
| 录制码率 | `8.0`（MB/s） | `record_bitrate: u32`（bps） | `u64` 换算 + 一位小数，范围 0.1～100 |
| 录制显示器 | 「主显示器（自动）」/「显示器 N · WxH · S%」 | `record_monitor: i32`（`-1` = 自动） | 下标 0 ↔ `-1`；下标 i ↔ `i-1` |
| API Key | 掩码 | `ai_api_key` | 原样；靠 `ES_PASSWORD` 掩码，`Text` 即可 |

这三个能过，剩下的字段都是平凡情况。

### 4.4 值生命周期

- **唯一真值** = `State.draft: Config`。
- `Bool` / `Choice`：点击后立刻写回 `draft`（不再维护 `checks` / `combos` 两个 `HashMap`）。
- `Text`：`EDIT` 内容在**保存前**和**失焦时** `commit_text()` → 调 `TextSet` 解析写回；
  解析失败**保留原值**并记下第一条错误（现有行为不变）。
- `validate()`：遍历 `form`，对每个 `Text` 字段的当前文本跑一次 `set` 干跑（写到 clone 上），返回第一条 `Err`。
  热键非空这类规则就写在它自己的 `set` 里。
- 保存：`commit_text()` → `validate()` → `draft.save(path)`。**不再需要"销毁前收集"**，`State.result` 可以删。
- 删除：`State::fill` / `State::collect` / `State::edit_text` / `validate.rs` 的 per-field `match`
  （`check_numeric` 的规则并入对应字段的 `set`，常量仍保留在 `validate.rs` 供单测引用）。

### 4.5 焦点顺序

`FOCUS_ITEMS` 由 form 生成：`sections → rows → widgets` + 行尾按钮 + 保存 + 取消。
截图设置仍是 **16 站**（13 字段 + 浏览 + 保存 + 取消），顺序与现在**完全一致**（§7 的 E2E 依赖它）。

## 5. 滚动视口

### 5.1 坐标与几何

两套坐标，不许混：

- **内容坐标**：`compute_layout` 的输出，从 `(0, 0)` 起，高度 = `content_h`（不含底部按钮）。
- **视口坐标**：客户区，底部按钮固定，不参与滚动。

```text
footer_y      = client_h - PAD - BTN_H                 // 固定底栏顶边
viewport      = (0, 0, WIN_W, footer_y)                // 可滚动区域
screen_y      = content_y - scroll.y                   // 内容 → 屏幕
scroll.max    = max(0, content_h + PAD - viewport.h)   // content_h 含底部留白
client_h      = min(content_h + FOOTER_GAP + BTN_H + PAD, work_h - 80)
                 且 >= MIN_CLIENT_H(480)
```

**关键约束**：内容不溢出时，`client_h` 必须与现行 `compute_layout` 算出的值**逐像素相同**
（回归测试 `default_size_unchanged` 锁定）——否则 `capture_settings_theme.ps1` 的尺寸判据会挂。

### 5.2 滚动状态

```rust
pub(crate) struct Scroll {
    pub(crate) y: i32,          // 当前偏移，0..=max
    pub(crate) max: i32,
    pub(crate) hover: bool,     // 悬停滚动条 → 变亮
    pub(crate) drag: Option<i32>, // 拖动起点：鼠标 y - thumb.y
}
```

```rust
fn clamp(&mut self);                       // 夹到 0..=max
fn wheel(&mut self, delta: i32, k: f32);   // 3 行/格
fn page(&mut self, dir: i32);              // 80% 视口
fn ensure_visible(&mut self, r: Rect, k: f32); // 最小移动量，留 8px 边距
fn thumb(&self, track: Rect) -> Option<Rect>;  // 内容不溢出时 None
```

### 5.3 输入映射

| 输入 | 行为 |
|---|---|
| 滚轮 | `WM_MOUSEWHEEL`，`delta/120 * 3 * ROW_H`；触控板高频小 delta 按像素累加（`acc` 余数） |
| `PgUp` / `PgDn` | 一屏的 80% |
| `Home` / `End` | 0 / `max` |
| `Tab` / `Shift+Tab` | 焦点移动后 `ensure_visible(目标控件)`；焦点被拉回视口内 |
| 拖动滑块 | 按下 thumb → `SetCapture` → `WM_MOUSEMOVE` 按比例映射 → 释放 |
| 点击轨道 | 上/下翻一屏 |
| 下拉菜单打开时 | 先 `close_combo`，再滚动（菜单位置在打开时算死，不跟随） |

滚轮消息在 `EDIT` 获得焦点时由 `DefWindowProc` 冒泡给父窗口，宿主能收到；若实测收不到，
给 `EDIT` 子类加 `WM_MOUSEWHEEL` 转发（§10 风险项）。

### 5.4 子控件同步

原生控件**创建一次**，按内容坐标摆放；滚动时只改位置，不销毁不重建：

```rust
// 一次批量移动，避免逐个 SetWindowPos 的闪烁
BeginDeferWindowPos(n);
for (hwnd, content_rect) in children {
    DeferWindowPos(hdwp, hwnd, None, x, y - scroll.y, w, h, SWP_NOZORDER | SWP_NOACTIVATE);
}
EndDeferWindowPos(hdwp);
```

- 窗口类加 **`WS_CLIPCHILDREN`**：父窗口双缓冲 `BitBlt` 时跳过子控件区域，滚动不闪。
- 滚出视口的控件**不隐藏**——父窗口会自动裁剪；只有命中测试、焦点、绘制需要判断是否与 `viewport` 相交。
- 滚动时 `InvalidateRect` 只失效 `viewport`，不动底栏。

### 5.5 绘制

`draw_scene(g, st, w, h)` 增加两步：

1. `g.clip_rect(viewport)` —— GDI+ 裁剪（`gdiplus.rs` 已有 `clip_rect` / `clear_clip`）。
2. 所有 `y` 加 `-scroll.y`；只画与视口相交的面板/行（面板整体相交即可，行级不再细抠）。

滚动条画在**最后**，位于视口右侧 `PAD` 内：轨道宽 6 逻辑像素，滑块最小高 24，圆角 `radius_scroll`。
内容不溢出时**不画**，也不占宽度（避免和现有截图判据冲突）。

### 5.6 主题新增键

| 键 | 默认 | 说明 |
|---|---|---|
| `scroll_track` | `#00000000`（透明） | 轨道 |
| `scroll_thumb` | `#40FFFFFF` | 滑块 |
| `scroll_thumb_hover` | `#66FFFFFF` | 滑块悬停/拖动 |
| `radius_scroll` | `3.0` | 滑块圆角（逻辑像素） |

缺省回退到 `Theme::DEFAULT`，**旧 `theme.dev.json` 不写这几个键也照常工作**。

## 8. 验收

### 8.1 单测（新增 ≥ 14 个，目标全绿）

| 用例 | 断言 |
|---|---|
| `form_covers_every_field` | 两个 Form 的字段并集 == `Field::ALL`，无重复 |
| `capture_form_field_order_matches_edit_order` | 文本控件顺序 == `[Hotkey, DefaultDir, LongMax, LongSearch, AiModel, AiEndpoint, AiApiKey, AiTimeout]` |

### 8.2 E2E（必须原样通过）

### 8.3 溢出滚动的人工验证（一次性，不入库）

1. 临时在 `capture_form` 末尾追加 6 个 `Text` 行（或把 `ROW_GAP` 临时改 26）→ 重新构建；
2. 预期：窗口高度封顶 `work_h - 80`，右侧出现滚动条，滚轮/`PgDn`/拖动可用，底栏「保存/取消」**始终可见**；
3. 截图留证到 `probes/e2e_out/`，改回代码。

单测 `scroll_extent_zero_when_content_fits` + 一个 30 行合成表单的布局用例覆盖溢出时的数学。

### 8.4 手工清单

- 125% / 150% DPI：滚动条 1px 缝、字号、行高
- 中文 IME：热键、目录、模型名输入正常
- 触控板：高频小 delta 不跳变
- 拖动窗口时滚动位置保持
- 主题热重载：滚动条颜色跟着变
- 键盘：Tab 走到视口外的控件时自动滚入

## 10. 风险与缓解

| 风险 | 触发信号 | 缓解 |
|---|---|---|
| 子控件移动闪烁 | 滚动时白边/抖动 | `DeferWindowPos` 批量 + `WS_CLIPCHILDREN` + 只失效视口 |
| E2E 下标漂移 | `e2e_settings.ps1` 改错字段 | 创建顺序由单测锁定；`record_settings` 类名与标题不动 |
| 焦点跑到视口外 | Tab 后看不见插入符 | `ensure_visible` + 单测 |
| 下拉菜单错位 | 滚动后菜单浮空 | 滚动前 `close_combo`；`open_combo` 用内容坐标换算 |
| 滚轮收不到 | EDIT 聚焦时滚不动 | `EDIT` 子类转发 `WM_MOUSEWHEEL` |
| 高 DPI 1px 缝 | 滚动条与边缘错位 | 统一走 `px()`；缩放后取整在同一个函数里 |
| 主题热重载漏刷 | 滚动条颜色不更新 | `repaint_all` 里本来就有全量 `invalidate`，滚动条随父窗口重绘 |

## 11. 何时重新考虑框架

满足**任一**条件时重启选型，且此时迁移成本已经很低（渲染层可替换，表单模型保留）：

| 触发条件 | 候选 |
|---|---|
| 设置 ≥ 5 页或字段 ≥ 30 个 | `egui`（纯 Rust、试点成本最低；需抬 MSRV、验中文 IME） |
| 设计稿由前端/设计系统产出，需要动效与富文本 | `wry` + WebView2 **子窗口**（`build_as_child`，保住 Win32 消息循环） |
| 需要跨平台 | `egui` / `slint`（授权需确认） |
| 设置变成带搜索、插件、实时预览的控制中心 | Tauri 2（需接受 WebView2 + 前端工具链） |
